## 用法

```
python3 scripts/voice_check.py <稿子.md> --clarity [--lecture] [--json] [--names <提纲.md>] [--hazards-only]
python3 scripts/voice_check.py --selftest [--clarity] [--letters 合辑路径]
python3 scripts/voice_check.py --baseline --extra <作者文本…> [--letters 合辑路径] [--per-doc]
```

- 退出码：0 无当前模式的硬伤；1 有硬伤；2 用法错误或找不到文件。退出码 0 不代表语义已核清，也不免除两项风格清理。`--selftest` 全过返回 0，否则 1。
- `--clarity`：H2–H4 保留命中位置供语义核读，只有 H1/H5/H6 决定退出码。`analyze(..., clarity=True)` 是对应的 Python API；不传时保留原有返回字段与判定，版本号更新为4.2（2026-10-17 加 H6，命令行选项没有变）。4.3（同日）加 H7，命令行选项仍没有变。
- `--lecture`：讲课档。报告头标注；硬伤规则不变；「我」与括号两行不打任何标记。
- `--json`：同样内容的机器可读输出（`hard`、`metrics`、`over_p90_count`、`exit_code` 等字段；第四版另有 `hazards`、`hazard_counts`、`hazard_skipped`、`clause_histogram`、`names_conditional_count`、`names`，见“隐患清单（第四版）”）。清晰模式新增 `mode: "clarity"`。`semantic_reviews` 沿用硬伤项的行号、代码、说明、原句字段：清晰模式里放 H2–H4 和 H7，H2–H4 不再出现在 `hard`；4.3 起默认模式也带这个字段，只放 H7。H7 另有 `trigger`、`pair_line`、`pair_end_line`，A 有 `length`、`overlap`，B 有 `ratio`、`contained`、`opening`、`matched`、`matched_sentence`、`echo_count`。
- `--names <提纲.md>`：读提纲名字表的“不许用”一栏，逐处报正文和标题里的禁用说法（隐患清单第九类）；提纲文件不存在时退出码 2。
- `--hazards-only`：只打印复核候选，供写手改稿时反复跑；默认列 H7 候选和原隐患清单，配合 `--clarity` 时也列 H2–H4 的语义复核候选。退出码仍由当前模式的硬伤决定。
- `--letters` 默认 `~/ficc-letters/letters.txt`。

查的范围：第一个 `# 附`/`## 附` 标题之前；跳过围栏代码、表格行（`|` 开头或含两个以上 `|`）、图片行和 HTML 注释；引用块（`>` 开头，包括案例框）照查，命中处标「〔引用块〕」；标题行在这组规则里只查 H4；H5 另查全文；H6、H7 再跳过清单行。隐患清单用同一范围（名字表禁用词另查标题行）。

H1–H6 的字面匹配方法没有改变。默认模式把 H1–H6 都记为硬伤，H7 两种模式都只进 `semantic_reviews`；现行清晰模式只把 H1/H5/H6 记入 `hard`，H2–H4 记入 `semantic_reviews`。实际路线图也会保留为候选，由人依据 FICCCompose.md C01 判断；脚本不会把候选自动认定为正确。核读与处置见 FICCVoice.md 7（V37–V40）及 `references/clarity-acceptance.md`。

**H1**：`【S数字`（含 `【S12】`、`【S3, S5】`）、`〔S数字〕`、`[src:`（不分大小写）；〔〕里出现文件名（.md .txt .py .json .csv .pdf .docx 等常见扩展名）、路径（`~/`、`./`、`/Users/`）或行号标记（三位以上的 `L120`、区间 `L12-L30`、`#L5`、`：L12`、`第 3 行`）。不算：〔九节〕〔2018.11〕〔L14、L16〕（讲义线名）〔来源：2025 年 4 月份月报〕，两份指引自己就这样注出处。

**H2**：只看正文前两段（一个非空行算一段，标题不算），再加前两个非引用段（开头是案例框时，看框后的两段）。命中下列任一项即算：本文旨在｜本篇旨在｜本文分为/分成/分别/分三……｜下面将从｜以下将从｜「本文/本篇/下文/以下/下面＋将/拟＋（重点、首先等副词）＋从/分为/围绕/讨论/梳理/回顾/介绍/分析……」｜同段「首先……其次……最后」｜「第一部分……第二部分」。
和 packet 字面写法的差别：「本文将」「本篇将」后面要紧跟一个交代安排的动词才算。《熊猫讲期权》第二段「第一，本文将大量使用案例而不是公式，第二，本文将会尽量削弱随机分析的存在」承诺的是方法，不是安排；按字面规则，范本过不了自检。

**H3**：连续 ≥3 行（空行不打断，其他任何行都打断），每行以 `-`/`*`/`+`（后跟空格）、`•` 等圆点、`1.`、`1、`、`1）`、`（1）`、`第一、`/`第一，`/`第一：`、`其一` 起头，去掉起头和 `**` 后不超过 20 字（字＝汉字＋英文字母＋数字，标点空格不计）。连续 ≥3 个同类的「一、」「（一）」短行、中间没有正文的，按清单处理，不按标题，同样受 H3 约束。「第一个办法：打多份工」这类小标题加冒号起段的写法不算起头。是否说清判断及各项关系，按 FICCVoice.md V10、V25 核读。

**H4**：标题指 Markdown `#` 标题，另认纯文本节标题，即以「第X章/节/部分」「一、」「（一）」起头的单行：去掉序号后不超过 40 字，中间没有句号、分号。合辑和范本都这样标节。命中条件有两种：
- 标题（去掉序号）含「不是……而是」「：不是」或「vs」；
- 与前一个同级标题（中间没有更高级的标题隔开）去掉序号后等长、不少于 6 字、标点骨架相同且非空。骨架指标题内部的标点序列，末尾的问号、冒号不计。
和 packet 字面写法的差别有两处。第一，骨架为空（标题里没有标点）不算，否则 FICCOutline 自己的「取舍节与收尾」「第一段怎么进」（各 6 字）、《九节》的「散户的动物精神」「好消息之一二三」都会因碰巧等长而误报。第二，公共前缀超过一半的不算（如上篇、下篇同题）。

**H5**：查全文，和上面的查的范围不同：`## 附` 以后、标题、表格行、引用块都查，只跳过围栏代码和行内反引号代码。每个「」『』记一处，报行号和前后各 12 个字符；书面档、讲课档一样。依据是用户2026-10-12的裁定。

**H6**：正文行里的全角分号“；”。范围与 H1 相同，查到第一个 `# 附`/`## 附` 为止，跳过围栏代码、表格行、图片行和标题行。清单行也跳过，即以 `-`、`*`、`+`（后跟空格）或 `1.`、`1．` 起头的行，前面可带 `**`。行内反引号代码先遮掉再查。引用块照查，命中处标“〔引用块〕”。一行记一处，说明里写这行有几个分号，报行号和第一个分号前后各 12 个字符。半角“;”不查。默认模式和 `--clarity` 都算硬伤，有一处即退出码 1。书面档、讲课档一样。依据是 FICCVoice.md V07 和用户2026-10-17的裁定：正文禁用分号，改成多个短句，表格与真清单例外。“一、”“（一）”“第一，”这类序号起头的行不算清单，照查。它们在公文体里是段落，H3 另按清单口径核读。

**H7**（4.3，2026-10-17；同日按 wave-4 甲、乙两稿校准为两种触发）：跨段重复。范围与 H6 相同，查到第一个 `# 附`/`## 附` 为止，跳过围栏代码、表格行、图片行、标题行、清单行和 HTML 注释，引用块照查。连续的正文行并成一段，空行分段，被跳过的行（标题、表格、清单行等）也结束一段，进出引用块也分段。只计汉字和数字：英文字母、标点、空白和 `**`、`__`、反引号都不计，比较也在只留汉字和数字的文本上做。两种触发：

- A 长串重合：两段有不少于 `H7_MIN_RUN`＝20 个计数字符的公共串。用 20 字符的片段建索引，一对段只报一次，报最长的一处；原句栏给原文里这一串的前 30 个字符，中间夹的英文和标点照原文显示。
- B 段首复述：第一段以后的每一段取首句，到第一个“。！？；”或“：”为止，冒号后面是证据，不算段首。去掉句首连接词（`H7_CONNECTIVES`：而且、所以、但是、可是、既然、那么、同时、其次、此外、不过、因此、于是、然而、先看、再看、更要紧的是、这个、第一，、第二，、第三，，可叠用）和“，”，计数字符不少于 `H7_ECHO_MIN`＝8 才比。比的对象是前面每一段的每一句（按“。！？；：”切）和句里的每个分句（按“，、”切，同样去掉句首连接词）。段首被包含在其中，或 difflib 相似度不少于 `H7_ECHO_RATIO`＝0.75，算一次复述，每对段取最好的一处。同一个前段被不少于 `H7_ECHO_GROUP`＝3 个后文段首复述，才把这些复述逐条报出；已由 A 报过的一对段不重复报。报告给前段与后段的行号、包含还是近似、相似度、该前段被复述的段首数、被复述的那一句和段首原文。

两种触发都只进 `semantic_reviews`，不计入 `hard`，不改退出码；`--json` 里 `trigger` 是 A 或 B，A 另有 `length`、`overlap`，B 另有 `ratio`、`contained`、`opening`、`matched`（被复述的句或分句）、`matched_sentence`（它所在的整句）、`echo_count`。依据是 FICCCompose.md C23 的检查项：承接段写成目录（C04、C06）、收尾重复开头（C17、C19），以及 C20 的预告与兑现。主旨段或承接句把后面几段的段首逐句照抄一遍，就是目录式的预告，不是链条上的一步。同一结论再提时要多带一层（C07）。一处回扣不报：C13 要求接缝回扣上一块，单个段首复述前文一句是正常写法，只有成组照抄才像目录。命中只说明字面重复，留哪一处、另一处怎么改，由人按这几条判。统一改写前后两版并排的工作稿（如 （作者草稿） 的 Compose 稿与 Voice 稿）会整段命中 A，这是文件结构造成的，不是正文问题。

## 密度记录与两项风格清理

每项给每万汉字的密度和原始次数，分母是查找范围内的汉字数（不含标题）。一个非空行算一段（中文稿不硬折行）；句子按 。！？ 切分。

| 项 | 怎么数 |
|---|---|
| 不是……而是 | 同一句里「不是」之后 30 字内出现「而是」，计一次 |
| 破折号—— | 两个以上连写的 —/― 计一处 |
| 段末升华 | 段末一句以 这就是｜这才是｜这正是｜归根结底｜归根到底｜说到底 起（前面可以有「而/所以/因此」） |
| 连续三短句 | 同段连续三句及以上、每句不足 15 字（字的算法同上），计一处 |
| 本质上等五词 | 本质上、值得注意的是、不难发现、换言之、总而言之，合计 |
| 无人称规范句 | 句首是 以下适用于｜不因（不含「不因为」）｜仅凭 |
| 「我们」 | 出现次数 |
| 「我」 | 后面不跟「们」的「我」（「我国」也算） |
| 括号插话 | 全角括号内 6–60 个汉字；纯英文术语括注不算插话 |
| 三连排比 | 同一句里 ≥3 个分句（按 ，；： 切）以同样两个汉字起头 |

**「！」怎么读**：标「！」要同时满足两条：密度高于基线表的90分位，出现不少于3处。统计本身不改变退出码。按用户2026-10-13裁定，只有“不是……而是”和破折号两行交稿前要改到不再标“！”；当前固定清理标准分别为每万汉字高于6.5、0.3，并且出现不少于3处。这是原有风格清理要求，不是歧义检测或清晰度证明，见 `references/clarity-acceptance.md`。脚本仍从基线表读取这两个数，因此重算基线时须保住它们（历史待办 FV-13 是改写为独立常数，本次不改计算）。其余各行只报数，作者语料两列只提供背景；“我们”偏低不打标记（用户2026-09-05裁定不设人称下限）。报告已纠正原来笼统的“只报数”说明。

“我”一行有“！”只报数，放行；破折号一行按用户2026-10-13裁定，标了“！”就要改。作者语料里这几行的情况见下面“历史与维护”。

## 隐患清单（第四版）

隐患清单是冷读席的候选清单，只报不拦：不改退出码，不打“！”，不设数量上限。逐条怎么处理见 FICCVoice.md V37–V40 和 `references/clarity-acceptance.md`（核出真实理解障碍就改，误报说明理由）。本机没有分词库，九类全用正则和字符规则，属于启发式，宁可少报。

查的范围同报数项：第一个附录标题之前的正文行，跳过围栏代码、表格行、图片行、HTML 注释；引用块照查，命中处标“〔引用块〕”；标题行不查，只有名字表禁用词查标题行。查之前先剥掉 `[src: …]`、`【S12】`、`〔S3〕` 这类内部标签（它们归 H1）、脚注记号、链接地址、加粗记号和行首的列表记号。

切分：句子按 。！？ 切，括号里的不切，句末的右引号跟着上一句，整句括注“（……。）”在右括号后切，以英文句点收尾的引语（“… growing.”）在右引号后切；分句按 ，；： 切，括号（）() 里的不切，两边都是数字的不切（千分位、时刻）；半角逗号、分号、问号不算界。下表的“开头”指去掉开头的引号、括号和空白之后。

| 类别 | 算 | 不算 |

### `--names`：名字表

名字表现为四栏（名字｜指什么与口径｜本篇写法｜不许用的叫法），只收自创或多种说法的名词（FICCOutline 4.2，用户2026-10-15）；找表的规则不变。

- 找表：提纲里第一个 Markdown 表，表头同时有含“名字”的一栏和含“不许用”的一栏，下一行是分隔行（`|---|`）；表到第一个不以 `|` 起头的行为止。找不到就在报告里写“提纲里没找到名字表，未查”，其余照常。
- “不许用”一栏：在括号外的 ，、； 处切开（括号里的逗号、顿号不切）；每项去掉括号及其内容，括号里的话记作“表里限定”，跟在备注里；含“除外”“照引”“写”的说明项整项丢掉；一项里有两个及以上引号词（正文里的“尖”“变尖”）就取这几个词，否则去掉引号用整项；不足 2 字的丢掉（“尖”“门”）。同一个说法出现在几行，应写成的名字用“或”合并。
- “名字”一栏（旧表叫“名字（简称）”）：去掉括号后在 ；／ 处切（半角 `/` 不切，“AAA/AA 级发行人”保持完整）；一项里有引号词（其余写“新增借款”）就取引号词；括号里的引号词（同段后文简称“低价贷款”）也算正名，但不写进“应写成”。这一栏空（不起名）时写“名字表 #N 的写法（不起名）”。
- 匹配：说法里字与字之间的空白可有可无（“K 形”也匹配“K形”）；以英文字母起止的说法，前后不能紧挨英文字母（IG 不匹配 BIG，bp 匹配 50bp、不匹配 bps）。
- 子串：命中处落在任何一个正名的出现位置之内就不报（禁用“杠杆”，“净杠杆”“杠杆率”“杠杆贷款”里的不报；禁用“困境贷款”而另一行的正名就是“困境贷款”，等于不报）。同一处被长短两个说法同时命中，只报长的。
- 范围：正文行加标题行；表格行不查（改动表一类照引表格因此不报）；命中落在《》书名号里的一律不报（引的是篇名，属照引）。
- 紧挨正名：命中处前或后零距离紧挨着它自己那一行的正名（“五家Hyperscalers”“Hyperscalers五家”；中间只隔空白也算零距离，“Hyperscalers 五家”同样不报），不报，`--json` 里也不列；紧挨的是别的行的名字（“尾部五家”）照报。
- 有条件与无条件：“不许用”一栏里带括号限定的说法（题目除外、单用作指标时、指 EBITDA 时、第一次之后、不带谁的、照引除外、另一个指标……）算“有条件”，机器不认限定；同一个说法在几行出现，只要有一行没带限定就算无条件。无条件的命中进主清单、计入 `hazard_counts`；有条件的命中另起一小节“有条件的禁用词（按表里限定人工判）”，文本最多列 10 条，其余进 `--json`，条数在 `names_conditional_count`；备注附“表里限定：……”原文，由冷读按限定判。

每条一行：`L<行号> 〔类别〕[〔引用块〕] 片段[｜备注]`。片段取命中所在的句子，超过 60 字时截取命中附近的 60 字，截掉的一头写“…”；命中处用〔〕标出（分句过多是整句，不加〔〕；的≥3 标整个分句或顿号并列项）。备注只在和类别说明不同时出现：分句数、“的”的个数、元话语主语、应写成哪个名字。每类最多列 40 条，多出的写“另有 N 条，--json 全列”。小表里分句过多只给 ≥6 的数，注“≥4 的见 --json”；名字表禁用词只给无条件的数，注有条件的另有几条。有条件的禁用词列在最后一小节，每条标“〔名字表禁用词·有条件〕”，最多 10 条。默认模式的命中、计数和退出码保持原样；报告文字已区分两项风格清理与清晰度核读，清晰模式另列 H2–H4 候选。

`--hazards-only`：打印文件名和隐患清单；配合 `--clarity` 时也打印 H2–H4 候选。退出码只由当前模式的硬伤决定。

`--json` 新增字段：
- `hazards`：`[{line, kind, text, hit, note, quote}]`，按行号排。`kind` 是九个类别名之一；`text` 是带〔〕的片段；`hit` 是命中的原文（分句过多是整句，的≥3 是整个分句或顿号并列项）；`note` 是备注；`quote` 表示在引用块里。分句过多的每条另有 `clauses`（分句数；≥4 的全列，文本只列 ≥6）；名字表禁用词的每条另有 `conditional`（true／false）和 `condition`（表里限定原文，无条件时是空串）。
- `hazard_counts`：`{类别: 条数}`，口径同文本小表：`分句过多` 只数 ≥6 的，`名字表禁用词` 只数无条件的；没给 `--names`、或提纲里没找到名字表时，`名字表禁用词` 是 `null`。
- `hazard_skipped`：`{"分句过多（列举句，未列）": N}`，分句≥4 的列举句数。
- `clause_histogram`：`{"4": n, "5": n, "6": n, …}`，分句≥4 的非列举句按分句数的分布。
- `names_conditional_count`：有条件的名字表命中条数；没查名字表时是 `null`。
- `names`：没给 `--names` 时是 `null`，否则是 `{file, rows, terms, conditional_terms, status}`。
- `--json --hazards-only` 默认输出 `file`、`version`、上面六个字段和 `semantic_reviews`（4.3 起默认模式也有，只放 H7）；配合 `--clarity` 时另有 `mode`，`semantic_reviews` 里另有 H2–H4。

## 自检

## 已知局限

- 一行算一段。硬折行的 Markdown 会把一段拆成几段，段末与同段两项会偏。
- 纯文本标题靠序号识别，没有序号的不认（《九节》的「这些勇士，现在在哪里？」按正文处理）。
- H2 只看前两段，后文再交代安排不管；「接下来我们将……」这类同义说法没收。H2–H4 都不能凭字面区别有效逻辑展开与表达问题，所以清晰模式只列候选。
- 短稿（不足 1500 汉字）的密度只作参考。
- 隐患清单是启发式。没有分词，“的”“这”“而”只看字面；“结果就是……”里的“结果”是主语，会被当成连接词报承前省略；分句多在作者自己的文本里也常见（≥6 个分句的句子《九节》25 句、《熊猫讲期权》109 句；≥4 的分别是 104、357 句），只能当候选。
- H7 只计汉字和数字，纯英文的重复不报；图题、数据标签这类汉字长串仍会命中 A（《熊猫讲期权》“中证1000股指、IM2403期货交易量和基差”）。B 只看字面，改写过的复述看不出来；成组门槛 3 是按甲、乙两稿定的，样本只有一对，子节点只有两个的短稿永远报不出 B。一行算一段的稿子里，相邻两行同一句话也会被当成两段报出。
- 名字表“不许用”一栏括号里的限定（题目除外、单用作指标时、第一次之后、照引除外）机器不认，只把这类命中另列为“有条件”，备注附限定原文；《》书名号里的不报。
- 而则并且的成对规则里，“非”按单字认，“非金融”“非上市”里的“非”也会让同句后面的“而”不报（三份试跑文本里没有出现这种情况）。
