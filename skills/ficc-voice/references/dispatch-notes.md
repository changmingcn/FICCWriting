# Dispatch details

T0 reads this when dispatching, as needed. Moved out of SKILL.md on 2026-10-17; the original sentences were only shortened, none deleted. The relay table and the acceptance table are in SKILL.md 2–3. Below, “writer” means the seat that drafts this node's body text: for a new draft, composer then writer; for a short piece, writer draft; for a wording-only edit, writer patch. Writing a piece from notes (从笔记成文) goes to ficc-writer draft for a short piece and to ficc-composer for a long one; builder does not write articles (2026-10-30).

## 1 packet

1. The COMMON packet is the shared packet head for all writers in the same round; a unit packet writes only what differs for its unit. Merge general rulings into the COMMON packet.
2. T0's rulings file has one section per unit number. A packet points only to its unit's lines and to the general rulings.
3. A ruling lists all known places where the same judgment lands (body text, headings, figure notes, change tables), and the subject, period, sample, and attribution of inference that must be kept. Within a node, fix the same confirmed defect in one pass.
4. A literal replacement whose old sentence, new sentence, and file are all settled is not dispatched to a writer. Merge the whole round into one patch packet (dynamic-workflow references/artifact-schema.md, Packet file), or send it to the owner who is still online.
5. For check and fix rounds, T0 attaches this round's rule excerpt (section number plus original text) to the COMMON packet; writers do not read the full rules. A patch packet marks itself (`mode: patch` on its own line, or patch as the role in its H1 title) and names references/voice-excerpt-patch.md (wording) or references/compose-excerpt.md (paragraphs); for a ficc-writer or builder dispatch the dispatch gate logs a reminder when it names neither, never a block. New facts in a patch packet are written in by paragraph, never piled at a paragraph's end (修补包的新事实按段落组织写入，不许堆在段尾). To organize the paragraphs of a whole node, read FICCCompose.md in full; to polish, read references/voice-excerpt-polish.md and open FICCVoice.md at a V number when its action is unclear; otherwise follow each card's mode table.
6. Placement records and relation sheets go in the task directory, file names `安放记录-<编号>.md` and `关系单-<编号>.md`.
7. The packet must attach the material excerpts and qualifiers this node uses (who, what they did, what is counted, period, unit, qualifier) and the original text of the 〔作者亲写·逐字〕 sentences. Relation sheet 2.6 and 2.7 record only positions; T0 extracts the original text by position and attaches it, and must not give only a path.
8. Short-piece merged mode: for a short piece (body text ≤600 Chinese characters, counted per O44, whatever the node's layer), dispatch one writer draft seat to do relay steps ④⑤ together, reading references/compose-excerpt.md first and references/voice-excerpt-draft.md and voice-excerpt-polish.md after (FICCVoice.md by V number), with no separate paragraph draft. A piece with child nodes, a section-level carry-over, or the whole piece's close also reads FICCCompose.md C04–C06 and C17–C19. A longer piece reads FICCCompose.md in full first. The result sheet lists truthfully the rule files and sections actually read. For a wording-only edit (a passage whose facts are tied out and that does not argue: SKILL.md 2), dispatch writer patch, step ⑤ only; a passage that argues goes as a short piece in writer draft mode per SKILL.md 2, and the packet carries SKILL.md 2's authorization sentences verbatim (from “A smoothing request” through “does not widen authorization”), so the writer holds the boundary from the packet alone; holding two roles does not widen authorization.

## 2 Writing units and to-do items

1. Outside this node, the writer changes only the table of contents and references (section numbers, headings, and back-reference names elsewhere that point to this node, the few characters in echo sentences that refer to this node, and bibliography entries). Body text elsewhere that must change goes on the to-do list; T0 routes the to-do items to that node's owner, and they may be merged into that node's next round, so each item need not get a round of its own. Each round still writes only that one node.
2. If maintaining the outline substantively changes a settled claim, content, or order, T0 dispatches the structurer to add the affected relations. Work that only carries out settled decisions or only aligns numbering (node numbers) is not judged again.
3. A return note states at least the location, the specific conflict, and the decision needed, and goes into the existing to-do lists (result-sheet to-dos, relation sheet 4, placement record 5); do not set up a separate ledger. Whom to return to: per SKILL.md 3. Recheck by the affected range; when an upstream change affects the whole text, check the whole text. The affected range is the changed-sentence table from `scripts/changed_sentences.py FROZEN CURRENT` (its 「凡有改动」 set: every row it lists, punctuation and paragraph-seam changes included): after a patch round the recheck wave's packets (writer check-clarity and cold-read, structurer check, outliner check) carry only this table, never the full draft as the object; a first check reads its full range. When dispatching composer check, attach the previous check result. Before any re-tick seat T0 runs `scripts/number_set_diff.py FROZEN CURRENT --units <the re-tick packet's unit list>`, and the re-tick packet carries that unit file: equal number tokens (each unit's numbers with sign, approximation or comparison marker, scale, unit and counting word, in order) open no re-tick seat (source-check.md, Validity of a check); a difference re-ticks only the units it lists; an unresolved id or a list that matches nothing gives no verdict (exit 3), so T0 fixes the list first; T0 reads its quantifier short list (大半、多数、过半、少数、近) by hand. Its output lists each differing unit with id, line, kind, frozen and current tokens and pair_confidence (high, low or unpaired; a low pair, matched away from its position, counts as a difference whatever its numbers), then the verdict line (fields and grammar: the docstrings of number_set_diff.py and changed_sentences.py). At the delivery edge T0 runs `shared-protocols/scripts/supersede.py` itself; no seat is opened.

## 3 Sweep-edit mode (optional)

Usable in rule sweep-edit rounds and revision rounds. A script first locates the hit sentences; set the granularity by the hit count: one writer per piece, or per three to five units. The writer holds the list of hit sentences, this round's rule excerpt, and one outline excerpt per unit (name table, this node, the adjacent nodes' conclusions, this node's rows in the relation sheet). Node permissions do not change; record diffs by node. On first use, trial it on one piece only and keep another piece on the old way as a control; record each piece's cost per round, the fix-level finding rate of the 标题级反驳席, and the share marked “本轮引入” (introduced this round).

## 4 Pacing

1. Rulings are batched per stage. A stage is one relay phase (outline, drafting, check, delivery: 提纲、起草、检查、交付) and closes when the user explicitly says 继续 or its acceptance is recorded; a message that hands items to T0 (such as 你自己定) is not 继续, and T0's own rulings join the open batch. Only when the batch closes does one sync wave (relation and annotation lines backfilled after the rulings; the structurer pass of 2.2 joins it) and one patch wave run. Before the batch closes T0 only records rulings and dispatches no sync or patch seat. Outline changes the writer truly needs before drafting (nodes, claims, order) are still made at once, by an outliner seat, with each change, and they trigger no sync or patch seat.
2. At the end of a campaign, build and upload only once.
3. Run the scripts only once at the writer's node level and once before submission. The seat that checks clear expression reads the script output in the writer's result sheet and does not run the scripts again.
4. For a node with a source list, the source-check seat also checks every “institution + date” in the body text against the list, item by item.

## 5 Supplements on relay and rulings (expanding SKILL.md 4)

1. After relay step ③, outliner maintain backfills relation lines and annotation lines per the relation sheet. A new node uses the same temporary number in both records; the outliner hands back the temporary-to-permanent and old-to-new number maps, and T0 passes them to the writer with the relation sheet.
2. Collect comments from trial pieces and new rules into one batch, install it into the rule files, then do one unified revision round.
3. Owners of to-do items: placement, selection, order, and length belong to the outliner; relations to the structurer; paragraph organization to the composer; sentences and wording to the writer.
4. When a fact the placement record keeps really must be deleted, the outliner reviews the placement again within the selection range the task allows, and then the structurer adds the affected relations.
5. The 标题级反驳席 (heading-level refuter seat; formerly the counter-view seat, card and model unchanged) catches heading-level overstatement: a wrong time window, a model's upper bound written as a finding, our inference written as the source's claim. Neither the cold read nor the tie-out catches these.
6. Run the two pre-submission scripts per references/clarity-acceptance.md. Judge review candidates by meaning; do not spoil an accurate expression to clear a flag. After changing a heading or section number of the four rule files, run scripts/xref_check.py before installing.
7. The author's model texts, references/exemplars.md, are kept for reference; no need to compare against them. Grounds, audits, and history, references/dev-notes.md, are not read for daily writing. FICCVoice's sources and maintenance record: references/FICCVoice-provenance.md. The glossary is references/glossary.md.
8. The writer may have a style of its own.
9. Update an existing draft in place by its stable Doc ID. Make HTML, PDF, or Word only when the user asks. When the user wants only the article, do not attach writing notes, self-assessment, or generic disclaimers.
10. Rule numbers: SKILL.md 4, item 13. Old-to-new map: references/migration-2026-10-17.md.

## 6 Outline slices (default)

Default from 2026-11-03 (wave 3 U10; the 2026-10-25 trial ended early): writer, composer and structurer seats receive the node slice (`node`) with its relation lines and never the full outline; only the outliner reads the outline through, and its check mode reads the view (item 4). Why: writing seats read a median of about 6.8 KB of the outline and none read it through, while patch seats sent without a rule excerpt read FICCVoice.md in full (dev-notes 54). Slices come from `scripts/outline_slice.py` (scripts/README.md). Run `nodes --check` first; a non-zero exit stops slicing. The outline file stays the one home (SKILL.md 1), and tie-out runs on it unchanged.

1. Unit packets: add the unit's ancestor chain (`chain`) and the name-table rows the unit uses, beside the unit's nodes. First drafts filter by the unit's nodes (`names --ids`). Fix and patch rounds also filter by the draft (`names --text <draft>`, union with `--ids`). Siblings' conclusions come from the relation sheet or `node` (FICCVoice V01). The cold read keeps the full name table (SKILL.md 2).
2. COMMON packet: keep the outline path (SKILL.md 1) and add one line: look up a node this packet lacks by number (`node`), and do not read the outline through.
3. Patch packets: apply §1 item 5 (ficc-writer card, patch mode).
4. Structurer check and later relate passes, the 标题级反驳席, outliner check and T0 read the brief view (`view`) as the tree. The structurer's first relate pass reads the brief view and the node slices it judges, as its card says. The view leaves out 把握, 标注 and 展开 lines and the head: pull the node (`node`) for them, and whenever a relation, a full-statement place or a source is in question. The 标题级反驳席 packet still carries the materials index, and carries 立论 as the object under check (state card block 5, 待检对象), never as State or a leading view (not block 4).
5. Record per piece: outline and rule-file bytes read by writing seats and T0; the heading-level findings of the 标题级反驳席, structurer placement objections, writer returns for a missing relation or full-statement place, and naming findings in the cold read, these four per 10,000 body characters (method: dev-notes 54). The 2026-10-25 trial piece's full four-metric baseline is unrecorded (dev-notes 54 holds the naming metric's figures and the method); the next task records its four in its task directory and dev-notes, and a later piece worse on those four than that record goes to T0 as a rollback candidate.

## 7 Inline seat

The scripts of this seat (`scripts/inline-seat/`) are not included in this package: they are bound to the author's model routing. The relay then runs with the `ficc-writer` card.

Default writer from 2026-11-05 (FC67; `basis` in the `deepseek-flash` route entry): the inline seat drafts and patches node bodies, and the `ficc-writer` card (T1E) is the backup or the comparison arm. Outline, relations, checks, finding maps and rulings stay on Claude seats and T0. The model has no tools and reads only what the packet inlines. The inline-seat loop is dispatched to a builder (FC1); T0 runs at most a single-node dry pack or a ≤3-node acceptance spot-check in-session. Scripts and their file conventions: `scripts/inline-seat/` (each script's `--help`; scripts/README.md).

1. Modes. `draft` writes one node's body, steps ④⑤ in one call (as §1 item 8); `patch` applies one node's rulings to its current body. A node the outline marks 不设开头段 gets its heading only.
2. Packet order, fixed for the prefix cache: role and hard lines; rule excerpts (identical for every node of the round); state card; materials; output contract. The hard lines forbid internal numbers, material ids and source anchors in the body (a source is an institution plus a date) and carry the long-sentence rule; name-table rows are only those the node uses (§6 item 1).
3. State card (Trace as State), seven blocks: 1 position (piece, parent, siblings); 2 lessons (hard lines); 3 current entries (outline slice, base text, source excerpts, name-table rows, rule excerpts); 4 trace (settled judgments, earlier nodes' trace lines, hooks to pick up); 5 constraints (first the node's own outline instruction, then cap, must-change sentences, do-not-write); 6 reading order; 7 metadata. The packer fills it from the outline slice and the placement record (placement-record-template.md 6); a field it cannot fill reads 无, never a guess.
4. Output contract: three sections in order, 思路 (reasoning, 6–10 numbered lines), 正文 (body), 回执 (receipt: count; facts carried, each with source and date; facts left out; differences from the base text; questions for T0; 3–6 lines starting 轨迹：). T0 reads the receipt questions before the next wave.
5. Parallel lanes: one lane per part; inside a lane nodes run in order and each node's trace lines feed the next node's block 4; lanes run in parallel. Patch rounds run every node in parallel. Never queue a whole piece.
6. Patch rulings: one ruling per node, in that node's section, quoting each sentence to change and saying how. General clauses stay in the COMMON part and are never copied into node sections, where the model applies them to sentences nobody named.
7. Apply checks (refuse or flag; a refusal re-runs that node only): internal labels and material ids in the body; in patch mode, any change to a sentence no finding names; a 不设开头段 node carrying more than its heading. The main and comparison arms write to separate run directories.
8. Findings to nodes: map check findings with `scripts/findings_map.py` (assembled-draft line to node, source line references stripped) before writing the rulings, then write one ruling per node from the map.
9. Assembly: join nodes in outline order; before delivery scan the full text for wording a ruling retired and for internal labels, then run the pre-submission scripts (§5 item 6).
10. Cost: each call is logged in the task's call ledger under the run's USD cap (task config); report its total beside the Claude ledger at settle.
