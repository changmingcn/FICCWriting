# Dispatch details

T0 (or the wave's `ficc-conductor`) reads this when dispatching, as needed. The relay table and the acceptance table are in SKILL.md 2–3. Below, “writer” means the seat that writes this node's body text, paragraphs and sentences in one pass (relay step ③, FICCVoice.md by the node's duty): for a new draft or a short piece, writer draft or the inline seat (§7); for a wording-only edit, writer patch. ficc-composer runs only as the optional paragraph-only comparison arm. Writing a piece from notes (从笔记成文) goes to ficc-writer draft or the inline seat, short or long; builder does not write articles (2026-10-30).

## 1 packet

1. The COMMON packet is the shared packet head for all writers in the same round; a unit packet writes only what differs for its unit. Merge general rulings into the COMMON packet. Its state card follows `shared-protocols/handoff.md` 2 (four blocks, `handoff.py card`); a ruling that applies beyond one node becomes a lesson line in the next round's COMMON, taken from the task's `trace.md`. The inline seat keeps its own card (§7 item 3).
2. T0's rulings file has one section per unit number. A packet points only to its unit's lines and to the general rulings.
3. A ruling lists all known places where the same judgment lands (body text, headings, figure notes, change tables), and the subject, period, sample, and attribution of inference that must be kept. Within a node, fix the same confirmed defect in one pass.
4. A settled literal replacement (old text, new text and file all decided) in any relay file (the living outline or the draft; a legacy placement record), heading edits included, is applied by T0 or the conductor with `python3 ~/.claude/skills/shared-protocols/scripts/replace_once.py --spec <spec.json> [--dry-run]` (spec: a JSON list of `{"file", "old", "new"}`; every old text must occur exactly once, else nothing is written and the offending entries are listed, exit 1), never by a seat; after an outline edit run `scripts/outline_slice.py nodes <提纲> --check`. Only text that needs a new judgment goes to a seat, the round's items merged into one patch packet.
5. For check and fix rounds, T0 gives this round's rules in the COMMON packet, as FICCVoice.md slices (section numbers) or as rule lines (id plus original text); writers do not read the full rules. A patch packet marks itself (`mode: patch` on its own line, or patch as the role in its H1 title) and names its slices: `FICCVoice.md §0, §3.1, §3.2 and §4` (the patch duty; add `§2` for paragraph work) with `references/clarity-acceptance.md` A02, or a non-empty `rule_sections` key for the inline seat; for a ficc-writer or builder dispatch the dispatch gate logs a reminder when it names none, never a block. New facts in a patch packet are written in by paragraph, never piled at a paragraph's end (修补包的新事实按段落组织写入，不许堆在段尾). To write or reorganize a whole node, read FICCVoice.md by the node's duty (SKILL.md 2) and open a rule by its id when its action is unclear; otherwise follow each card's mode table.
6. The living outline `<文稿>-提纲.md` sits beside the draft (SKILL.md 1) and holds placement and relations; new writing opens no placement record or relation sheet. A legacy or rewrite run that still keeps a placement record files it in the task directory as `安放记录-<编号>.md` (references/placement-record-template.md).
7. The packet must attach the material excerpts and qualifiers this node uses (who, what they did, what is counted, period, unit, qualifier) and the original text of the 〔作者亲写·逐字〕 sentences. The outline's fact anchors (`@doc:Lx–Ly`, 资料索引.md ids) and 〔作者亲写·逐字〕 marks record only positions; T0 (in living mode the packer, §7 item 17) extracts the original text by position and attaches it, and must not give only a path.
8. Short-piece merged mode: for a short piece (body text ≤600 Chinese characters, counted per O44, whatever the node's layer), dispatch one writer draft seat to do relay step ③ in one pass from the FICCVoice.md leaf slice (§0, §2, §3.1, §3.2 and §4), with no separate paragraph draft. A piece with child nodes, a section-level carry-over, or the whole piece's close reads the lead slice (adds §1: C04–C06 and C17–C19). A longer piece reads the same slices node by node. The result sheet lists truthfully the rule files and sections actually read. For a wording-only edit (a passage whose facts are tied out and that does not argue: SKILL.md 2), dispatch writer patch with the patch slice (§0, §3.1, §3.2 and §4); a passage that argues goes as a short piece in writer draft mode per SKILL.md 2, and the packet carries SKILL.md 2's authorization sentences verbatim (from “A smoothing request” through “does not widen authorization”), so the writer holds the boundary from the packet alone; holding two roles does not widen authorization.

## 2 Writing units and to-do items

1. Outside this node, the writer changes only the table of contents and references (section numbers, headings, and back-reference names elsewhere that point to this node, the few characters in echo sentences that refer to this node, and bibliography entries). Body text elsewhere that must change goes on the to-do list; T0 routes the to-do items to that node's owner, and they may be merged into that node's next round, so each item need not get a round of its own. Each round still writes only that one node.
2. If maintaining the outline substantively changes a settled claim, content, or order, T0 dispatches the structurer to add the affected relations. Work that only carries out settled decisions or only aligns numbering (node numbers) is not judged again.
3. A return note states at least the location, the specific conflict, and the decision needed, and goes into the existing to-do lists (result-sheet to-dos; the living outline's to-do items for other nodes, FICCStructure.md §6.2); do not set up a separate ledger. Whom to return to: per SKILL.md 3. Recheck by the affected range; when an upstream change affects the whole text, check the whole text. The affected range is the changed-sentence table from `scripts/changed_sentences.py FROZEN CURRENT` (its `凡有改动` set: every row it lists, punctuation and paragraph-seam changes included): after a patch round the recheck wave's packets (writer cold read with clarity, structure check) carry only this table, never the full draft as the object; a first check reads its full range. When dispatching a structure check, attach the previous check result. Before any re-tick seat T0 runs `scripts/number_set_diff.py FROZEN CURRENT --units <the re-tick packet's unit list>`, and the re-tick packet carries that unit file: equal number tokens (each unit's numbers with sign, approximation or comparison marker, scale, unit and counting word, in order) open no re-tick seat (source-check.md, Validity of a check); a difference re-ticks only the units it lists; an unresolved id or a list that matches nothing gives no verdict (exit 3), so T0 fixes the list first; T0 reads its quantifier short list (大半, 多数, 过半, 少数, 近) by hand. Its output lists each differing unit with id, line, kind, frozen and current tokens and pair_confidence (high, low or unpaired; a low pair, matched away from its position, counts as a difference whatever its numbers), then the verdict line (fields and grammar: the docstrings of number_set_diff.py and changed_sentences.py). At the delivery edge T0 runs `shared-protocols/scripts/supersede.py` itself; no seat is opened.
4. Patch default: one patch round plus one targeted recheck of the changed sentences (item 3, `scripts/changed_sentences.py`). A further round runs only for an open material defect and rechecks only that defect (CLAUDE.md, Proportion). Patch bounds: references/clarity-acceptance.md A02.

## 3 Sweep-edit mode (optional)

Usable in rule sweep-edit rounds and revision rounds. A script first locates the hit sentences; set the granularity by the hit count: one writer per piece, or per three to five units. The writer holds the list of hit sentences, this round's rule slices, and one outline excerpt per unit (name table, this node, the adjacent nodes' conclusions, this node's 分担／接前／关键边表 rows). Node permissions do not change; record diffs by node. On first use, trial it on one piece only and keep another piece on the old way as a control; record each piece's cost per round, the fix-level finding rate of the 标题级反驳席, and the share marked “本轮引入” (introduced this round).

## 4 Pacing

1. Rulings are batched per stage. A stage is one relay phase (outline, drafting, check, delivery: 提纲, 起草, 检查, 交付) and closes when the user explicitly says 继续 or its acceptance is recorded; a message that hands items to T0 (such as 你自己定) is not 继续, and T0's own rulings join the open batch. Only when the batch closes does one sync wave (relation slots updated after the rulings; the structurer pass of 2.2 joins it) and one patch wave run. Before the batch closes T0 only records rulings and dispatches no sync or patch seat. Outline changes the writer truly needs before drafting (nodes, claims, order) are still made at once, by an outliner seat, with each change, and they trigger no sync or patch seat.
2. At the end of a campaign, build and upload only once.
3. Run the scripts only once at the writer's node level and once before submission. The seat that checks clear expression reads the script output in the writer's result sheet and does not run the scripts again.
4. For a node with a source list, the source-check seat also checks every “institution + date” in the body text against the list, item by item.

## 5 Supplements on relay and rulings (expanding SKILL.md 4)

1. At relay step ② the structurer writes 分担, 接前 and 关键边表 rows straight into the living outline; no backfill pass follows. A node it needs goes to the outliner as a 安放异议 under a temporary number; the outliner hands back the temporary-to-permanent and old-to-new number maps, and T0 passes them to the writer with the node slice.
2. Collect comments from trial pieces and new rules into one batch, install it into the rule files, then do one unified revision round.
3. Owners of to-do items: placement, selection, order, and length belong to the outliner; relations to the structurer; paragraph organization, sentences and wording to the writer (FICCVoice.md; the composer only in a comparison arm).
4. When a fact the outline places really must be deleted, the outliner reviews the placement again within the selection range the task allows, and then the structurer adds the affected relations.
5. The 标题级反驳席 (heading-level refuter seat; formerly the counter-view seat; card and model: `shared-protocols/model-tiers.md`, Task seat profiles, top-review) catches heading-level overstatement: a wrong time window, a model's upper bound written as a finding, our inference written as the source's claim. Neither the cold read nor the tie-out catches these.
6. Run the two pre-submission scripts per references/clarity-acceptance.md. Judge review candidates by meaning; do not spoil an accurate expression to clear a flag. After changing a heading or section number of the three rule books or clarity-acceptance.md, run scripts/xref_check.py before installing.
7. The author's model texts, references/exemplars.md, are kept for reference; no need to compare against them. Grounds, audits, and history, references/dev-notes.md, are not read for daily writing. FICCVoice's sources and maintenance record: references/FICCVoice-provenance.md. The glossary is references/glossary.md.
8. The writer may have a style of its own.
9. Update an existing draft in place by its stable Doc ID. Make HTML, PDF, or Word only when the user asks. When the user wants only the article, do not attach writing notes, self-assessment, or generic disclaimers.
10. Rule numbers: SKILL.md 4, item 13. Old-to-new map: references/migration-2026-10-17.md.

## 6 Outline slices (default)

Writer, composer and structurer seats receive the node slice (`node`) with its relation slots and never the full outline; only the outliner reads the outline through, and check seats read the view (item 4). Slices come from `scripts/outline_slice.py` (scripts/README.md). Run `nodes <提纲> --check --closes` first; a non-zero exit stops slicing, and its `CLOSE-*` lines go to the outliner (maintain) as its work list. An outline carried over from a piece built before 2026-11-11, with no 收尾 line in it, runs `--check` alone until its next outliner maintain, which adds the lines. The outline file stays the one home (SKILL.md 1), and tie-out runs on it unchanged.

Before relay step ③, run `outline_slice.py check-0to1 <提纲>`: gates Z-SWAP, Z-DENOM, Z-Q, Z-SHARE (N0 included), Z-EDGE, Z-FACT, Z-QUOTE, Z-PARA and Z-SIGN, the script half of the Outline Gate (FICCOutline.md §9) and the Structure Gate (FICCStructure.md §7). Exit 2 on a hard finding stops the writing step, and each line goes to the owner of its slot (SKILL.md 3). A heavy node under `段：不拆` is a hard Z-PARA.

Maintain loop before relay step ③ (required, one pass). After the structurer's relate pass, run `check-0to1` on the outline; for a seat without tools (a foreign engine), the host runs it and pastes the raw lines into the next packet. Any hard line or open 安放异议 sends the outline to one outliner maintain pass, fed only those raw lines and the objections, with no other hint: the outliner narrows, splits or re-places in its own slots (FICCOutline.md O62, O63), and a hard line inside a relation slot goes to the structurer for that slot (a single maintain call whose packet grants both scopes does both). Re-run `check-0to1`: 0 hard opens step ③; a hard line left after that pass goes to T0 (narrow, research, or record the limit), never a second silent loop.

`outline_slice.py fields` prints the living outline as JSON (tree head, card, edges, the slot fields per node) and is the one parser of 事实, 算式, 消歧, 段 and 关键边表 rows.

1. Unit packets: add the unit's ancestor chain (`chain`) and the name-table rows the unit uses, beside the unit's nodes. Pass all the unit's node ids to one `chain` call: each ancestor is printed once (heading, its own 〔标题〕, task line), and a unit node is not repeated as an ancestor. When an ancestor's 收尾 line names a node whose end the unit holds, the chain prints a `收尾（本单元写…）` line under that ancestor: the unit writes that close, gathering and handing on what the line names, without restating the claim in other words (FICCVoice.md C17); it is a duty, not background. First drafts filter by the unit's nodes (`names --ids`). Fix and patch rounds also filter by the draft (`names --text <draft>`, union with `--ids`). Siblings' conclusions come from the living outline (`node`; FICCVoice.md V01). The cold read keeps the full name table (SKILL.md 2).
2. COMMON packet: keep the outline path (SKILL.md 1) and add one line: look up a node this packet lacks by number (`node`), and do not read the outline through.
3. Patch packets: apply §1 item 5 (ficc-writer card, patch mode).
4. The structure check, later relate passes, the 标题级反驳席, outliner check and T0 read the brief view (`view`) as the tree. The structurer's first relate pass reads the brief view and the node slices it judges, as its card says. The view leaves out 把握, 标注 and 展开 lines and the head: pull the node (`node`) for them, and whenever a relation, a full-statement place or a source is in question. It prints 收尾 lines. The 标题级反驳席 packet still carries the materials index, and carries 立论 as the object under check, outside the state card, never in it as settled or a leading view (`shared-protocols/handoff.md` 2: an independent check gets blocks 1 and 2 only).

## 7 Inline seat

The scripts of this seat (`scripts/inline-seat/`) are not included in this package: they are bound to the author's model routing. The relay then runs with the `ficc-writer` card.

Default writer (FC67): the inline seat drafts and patches node bodies, and the `ficc-writer` card is the backup or the comparison arm. Outline, relations, checks, finding maps and rulings stay on Claude seats and T0. The model has no tools and reads only what the packet inlines. The inline-seat loop is dispatched to a builder (FC1); T0 runs at most a single-node dry pack or a ≤3-node acceptance spot-check in-session. Scripts and their file conventions: `scripts/inline-seat/` (each script's `--help`; scripts/README.md).

1. Modes. `draft` writes one node's body, relay step ③ in one call (as §1 item 8); `patch` applies one node's rulings to its current body. A node the outline marks 不设开头段 gets its heading only.
2. Packet order, fixed for the prefix cache: role and hard lines; rule slices (the same for every node of one duty in the round); state card; materials; output contract. The hard lines forbid internal numbers, material ids and source anchors in the body (a source is an institution plus a date) and carry the long-sentence rule; name-table rows are only those the node uses (§6 item 1).
3. State card (Trace as State), seven blocks: 1 position (piece, parent, path to the root, siblings); 2 lessons (the hard lines, then at most five task or line lessons from the task's `trace.md`, newest first, when `pack_node.py --trace-file` or the config key `task_trace` names it); 3 current entries (outline slice, base text, source excerpts, name-table rows, rule slices); 4 trace (settled judgments, earlier nodes' trace lines, hooks to pick up); 5 constraints (first the node's own outline instruction, then cap, must-change sentences, do-not-write), and a 收尾（本单元写…） line of the chain is lifted into block 5 (draft: the last paragraph writes that close; patch: nothing changes unless a ruling names it); 6 reading order; 7 metadata. The packer fills it from the living outline (item 17), or in a legacy run from the placement record (placement-record-template.md 6); a field it cannot fill reads 无, never a guess.
4. Output contract: three sections in order, 思路 (reasoning, 6–10 numbered lines), 正文 (body), 回执 (receipt: count; facts carried, each with source and date; facts left out; differences from the base text; questions for T0; 3–6 lines starting 轨迹：). T0 reads the receipt questions before the next wave.
5. Parallel lanes: one lane per part; inside a lane nodes run in order and each node's trace lines feed the next node's block 4; lanes run in parallel. Patch rounds run every node in parallel. Never queue a whole piece.
6. Patch rulings: one ruling per node, in that node's section, quoting each sentence to change and naming only the rule and the form action (split, merge, delete, move, active voice, a banned word, the name-table name). Never prescribe replacement wording, direction, cause, certainty, holder or unit: route a content gap to the tie-out seat as a question (`inline_guards.py lint` strips such prescriptions before packing, G1; references/clarity-acceptance.md A01). A tie-out answer that fixes a fact returns by T0: in an inline-seat run it enters the node through a `必改句` row, an inline `[核对席]` bullet in the node's patch section (lint verifies its new numbers against B/C; a `## n（核对席）` heading there would end the section), or `apply_node.py --answer`, and a settled literal replacement through `replace_once.py` (§1 item 4) on the assembled final is for the final post-assembly step only. General clauses stay in the COMMON part and are never copied into node sections, where the model applies them to sentences nobody named.
7. Apply checks (refuse or flag; a refusal re-runs that node only): internal labels and material ids in the body (in living mode also the node's fact and edge ids); in patch mode, any change to a sentence no finding names; a 不设开头段 node carrying more than its heading; a B-grade patch whose net CJK count grows, on every attempt (U5a; references/clarity-acceptance.md A02). The main and comparison arms write to separate run directories.
8. Findings to nodes: map check findings with `scripts/findings_map.py` (assembled-draft line to node, source line references stripped) before writing the rulings, then write one ruling per node from the map.
9. Assembly: join nodes in outline order; before delivery scan the full text for wording a ruling retired and for internal labels, then run the pre-submission scripts (§5 item 6).
10. Cost: each call is logged in the task's call ledger under the run's USD cap (task config); report its total beside the Claude ledger at settle.
11. Task profile (config `task_profile`): `draft` (default) writes from the living outline (living mode, item 17), or in a legacy run from the placement record the config names. `rewrite` is a pure voice rewrite of the frozen base: every outline node not skipped is planned, with or without a placement section (O36); no number token may be added (V26); opening detail relocation is on unless the config sets `allow_opening_detail_relocation` false (FICCOutline.md O73). `--mode rewrite` is an alias, and it conflicts with a config that says `draft`.
12. Fact guards (config `guards_mode`, default `refuse`): before the call, `inline_guards.py scan` puts the G rows (holder, keep subjectless, recompute needed) into the pack, scanning the base, or in living mode the source excerpts, 算式 rows and 消歧 quotes; at apply, `inline_guards.py verify` checks the staged `## 正文` clause by clause against the frozen fact source. A HARD_REJECT is not published under `refuse`; `warn` records it and publishes; `off` skips verify and lint. PUBLISH_WITH_CANDIDATES publishes and appends its candidates, `class: semantic` ones included, to `<run_root>/must-tieout-candidates.jsonl` for the tie-out seat. voice_check hard errors (H1, H5, H6) and banned name-table words are never published in any mode; H10 and `重段待处置` are review rows (item 20).
13. Commit point and trace: a node counts as applied only when apply_node exits 0. `<drafts>/acceptance/<NODE>.json`, written last under the node lock, is its one commit point. Lane and arm traces are rebuilt from its `propagable_trace` in outline order (an empty list clears the node's old lines); `quarantined_trace` lines travel only after the tie-out seat clears them (`inline_guards.py release-trace`). In a 0→1 draft, paragraph openings often raise G-ADDED candidates, so a trace line that quotes an opening stays quarantined until it is released.
14. `## 思路` is diagnostic: its guard-row binding lines and its opening-thesis line are checked and noted (`check.json`, `verify.diagnostics`), but they never reject a node or clear a `## 正文` finding. Only `## 正文` is gated.
15. Retry and backup: a failed first attempt gets one retry whose request ends with a structured English failure report (failed field, body sentence, frozen source anchor, forbidden action). A second failure writes `<run_root>/escalations/<NODE>.json` and hands that one node to the backup seat, the `ficc-writer` card (config `escalate_route` records the route), with the same evidence and checks. When escalated distinct nodes pass `circuit_breaker` (0.25) of the run's planned nodes, the run prints a stop-lane warning.
16. Blind review: export drafts with `apply_node.py --strip-header PATH… --out-dir DIR` before any blind read. It drops the `<!-- inline-seat: run=… -->` line, which names the run, arm and cell; DIR may not be a source directory.
17. Living mode (0→1 draft): config `task_profile` draft with `placement` and `base_text` null or absent. The living outline is the only plan, read through `outline_slice.py fields` (§6) and never re-parsed; no label is required (`labels.source` defaults to `src`). Config `sources` maps each doc name to its path for fact anchors `@doc:Lx–Ly`; `materials_index` (资料索引.md, lines such as `E012 … @doc:L85–L90`) resolves a fact given by id alone. The pack holds: A, the node block, its chain and the 关键边表 rows touching the node, with status; C, its 写全 facts resolved to source lines, with 回指 and 留表 as pointers; R, the signed 算式 rows; M, the 消歧 rows. Block 5 carries the 段 plan (one paragraph per 段 row, its facts only), and the cap is the 展开 line's 上限N字. A draft with `base_text` but no placement is still refused.
18. Rule slices (config `rule_sections`): `{"file": "FICCVoice.md", "duties": {"leaf": [...], "lead": [...], "patch": [...]}}`, by default leaf `0, 2, 3.1, 3.2, 4`, lead adds `1`, patch `0, 3.1, 3.2, 4`. Lead is N0, a parent with its own opening, or a leaf its chain's 收尾 line assigns. A key matches a `##` or `###` heading whose first token is the key and runs to the next heading of the same or higher level. Since 2026-11-21 (W3a) `rule_sections` defaults to true (`{"file": "FICCVoice.md"}`) and `rule_excerpts`/`patch_rule_excerpts` to `[]`: a config that leaves it out slices by duty; one that lists its own excerpts without `rule_sections` keeps the excerpt path; `false` or `null` turns sections off, and an empty excerpt list then refuses.
19. `derivations.json`: the pack freezes the node's signed 算式 rows to `<run dir>/derivations.json` as inline_guards derivation rows (ids `D<k>`), with the tree revision and the node block's sha256; unsigned rows are listed as not usable and attest nothing. Retry and split copies carry the file, and apply verifies against it.
20. Hard refusals and draft gates. Pack refuses (exit 2) a body leaf with no resolved 写全 fact; an unresolvable fact anchor (a doc not in `sources`, an id not in `materials_index`, or lines outside the doc); a missing, empty or doubled rule section, or a missing rule file. Apply refuses a stale tree (the outline's tree revision, or the node block's sha256, changed since the pack: repack the node). In a draft, `inline_guards` gives a hard G-NEWNUM to a metric number found neither in the source excerpts nor in a signed 算式 row (算在树上，叶席零新数, FICCVoice.md V26). A signed row counts only when the sentence names its metric (or its denominator with a share cue); otherwise it is a hard G-DERIV. A missing row is reported in 回执 as `缺算式行｜拟求量｜操作数@锚点` and goes to the outliner, never computed in the body. voice_check v4.7's H10 (over ten sentences or 400 CJK characters) is a hint, and a paragraph with ≥30 number strings is `重段待处置`; neither blocks publication, but each `重段待处置` is disposed of before delivery (references/clarity-acceptance.md 3).
